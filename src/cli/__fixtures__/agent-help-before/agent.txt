Usage: elanous agent [options] [command] [text...]

Single-turn agent — same as `chat` but with the tool loop on by default
(Read/Grep/Glob/ListDir/Edit/Write + Bash). Use this when the LLM needs to
inspect files / run commands / debug itself.

Arguments:
  text                                            Prompt text for the single-turn agent.

Options:
  --new                                           Start a new session (the default since 0.2.31 — kept for compatibility)
  --continue                                      Continue the active session instead of starting a new one
  --resume [id]                                   Continue a session: the given id (or unique prefix), or the active session when no id is given. A word after --resume that is not session-id shaped (hex uuid) is read as the prompt, not the id.
  --session <id>                                  Continue an explicit session (id or unique prefix). Overrides --new, --continue and --resume.
  --json                                          Emit a single JSON line {sessionId, provider, model, reply, logPath, budget} instead of streaming text + ui.info trailer. Stable shape for LLM self-spawn.
  --no-tools                                      Disable the tool loop and fall back to text-only chat (for benchmarking / parity with `chat`).
  -h, --help                                      display help for command

Commands:
  dispatch [options] <subagent_type> <prompt...>  Spawn one sub-agent from the terminal and print its final message. Observe with `elanous logs --category agent.spawn` / `--category agent.done` — the printed cid pairs the two.
