elanous 는 어떻게 도나

· 2026-09-22 · ⛔ 이 문서는 「수」를 박지 않는다. 각 칸에 «재는 명령»이 붙어 있다. 🔗 RFC 공진화 · PRFAQ

한 문장​

말 한 줄에 눈·손·기억이 한꺼번에 도는 자기치유 코딩 하니스 — 에이전트가 에이전트를 개발한다.

❶ 전체 — 한 문장이 병합된 변경이 되기까지​

 사람 / 에이전트 세션
        │  "이 파일의 테스트를 붙여라"          ⬅ 입구: harness say · harness ask · /harness · TUI 고정구

 │                  마커: 대상 경로 · GoalType · 불변식 · 경계 ·      │
 │                        판정 신호(조건 / 관측 / 기대)               │
 │                  📏 bun scripts/ask-marker-check.ts <ask>         │
 └──────────────────────────────────────────────────────────────────┘
        ▼

 │                  ⬇ 노드 어휘는 ❷ 를 보라 — «되돌아가는 간선»이 있다 │
 └──────────────────────────────────────────────────────────────────┘
        ▼
 ┌──────────────────────────────────────────────────────────────────┐

그 셋을 떠받치는 셋 — 눈 · 손 · 기억​

👁️ 눈    elanous pty snapshot <ref>        남의 화면을 «소유권 없이» 읽는다 (--ansi 면 SGR 까지)
         firecrawl · omni-crawl · aside · CDP/Chrome        ⚠️ 상당 부분이 «빌린 것»이다 (❹)
✋ 손    툴 루프 Read/Grep/Glob/ListDir/Edit/Write + Bash
         elanous pty text|key <ref>        밖에서 실 TUI·자식에 «입력»한다 (크로스-프로세스)
🧠 기억  elanous memory (user|feedback|project|reference) — 매 턴 주입
         elanous self recall               자기 구현 이력

🔑 차별점은 셋이 «같이» 도는 것이다. 대부분의 에이전트는 셋 중 하나만 잘한다. 🔲 안 쟀다: 한 요청 «안»에서 셋이 몇 번 맞물리는지. 지금 이 주장은 «구성 요소»로만 참이다.

❷ 그래프 — 「다이나믹 ⊕ 리지드」는 이미 선언으로 있다 (정정 2026-09-22 · 이 축에서 내 세 번째)​

⛔ 이 문서는 이 절을 두 번 틀리게 썼다. 둘 다 적어 둔다 — 다음 창이 같은 자리를 밟지 않도록.

1차 «하니스와 wf 사이에 이음새가 없다»      → 틀렸다. orchestrator.ts:5060 이 이미 wf 를 돌린다
2차 «위상이 코드에 박혀 골이 못 바꾼다»       → 틀렸다. 위상은 YAML 선언이고 골 타입이 고른다
🔑 두 번 다 ***코드를 안 누르고 문면으로 판정***했다. 세 번째에야 실물에 물었다.

ⓐ 실측 — 위상은 «선언»이고 운영이 그것을 쓴다​

📏 재는 명령:

bun -e "import {GRAPH_TEMPLATES, GRAPH_TEMPLATES_SOURCE} from './src/self-implement/graph-templates.ts'; \
  console.log(GRAPH_TEMPLATES_SOURCE, Object.keys(GRAPH_TEMPLATES))"
source          yaml                (⊕ builtin-fallback 갈래가 있으나 지금은 yaml 이 이긴다)
디렉토리        graphs/
선언된 그래프   7 — self-implement · research-loop · document-loop · operate-loop
                    ad-loop · default-loop · plan-loop
self-implement  author → plan → decompose → implement → gate → review → rework
                → main-sync → regate → open-pr → merge          (11노드)
간선            gate → [rework | review | main-sync | open-pr]   ← «분기»가 선언에 있다
                review → [rework | main-sync | open-pr] · rework → implement (되돌아간다)
노드 계약       inputs · tools · outputs 가 노드마다 선언된다

🔎 반증 명령이 코드에 이미 있다: goalTypesWithoutTemplate() → [] ⇒ 골 타입 넷(implement·research·document·operate)이 전부 템플릿을 갖는다.

ⓑ 그런데 선언이 실행을 «몰지» 않는다 — 여기가 진짜 남은 칸​

checkPipelineTraversal(observedNodes, terminalNode)   ← «관측된 걸음»을 선언과 대조한다
이벤트 이름                                            pipeline-traversal-shadow
                                                       ↑ 이름이 스스로 «그림자»라고 말한다

🔑 선언은 비추고 있다. 몰지는 않는다.​

실행 제어는 여전히 오케스트레이터(TS)에 있고, YAML 은 모양을 선언하고 어긋남을 «보고»한다. ⇒ 남은 칸의 이름은 **「이음새 만들기」도 「넓히기」도 아니고 ⟪선언 → 실행 권한⟫**이다. ⚠️ 그림자로 둔 것은 의도일 수 있다 — 뒤집는 것은 위험한 변경이라 그렇게 시작하는 것이 옳다.

ⓓ wf 와의 관계 — 이음새는 «한 칸»에서 쓰인다​

src/self-implement/orchestrator.ts:5060   runWorkflowToCompletion({ workflow: reworkBudgetWorkflow, … })
src/self-implement/rework-budget-judgment.ts · classify-shadow.ts   executeClassifyNode

하니스의 판정 계약은 지금 rework-budget@v1 하나뿐이고, 그 하나가 wf 로 돈다. ⇒ 「wf 를 살린다」의 첫 칸은 판정을 하나 더 «선언»으로 옮기는 것이다(재발명 아님 · 본보기가 있다).

❸ 3축 — intake · workflow · task manager (대표 "3축도 원활하게 돌아갔으면")​

「말만 하면 이뤄진다」의 실체는 wf 하나가 아니라 문장을 받아 쪼개고 전체를 도는 세 축이다.

            실제 배선: TaskStore · createMission · triageGoal · resolveDomain
                       autoDecomposeMission · shouldPhaseDecompose · saveMissionOrigin

🚦 인테이크의 «문»은 셋이고, 선언된 채널 여섯 중 셋은 생산자가 없다 (재측 2026-09-22)​

🔴 정정 — 이 절은 처음에 "문이 «하나»(telegram)" 라고 썼고 틀렸다. 그때 쓴 자가 rg "from '…intent-gate/'" 라 정적 import 만 봤는데, 세 문 중 둘이 동적 await import(…) 였다. 그 절은 마지막 줄에 «이 자는 동적 경로를 못 본다»고 스스로 적어 두고도 머리말과 결론에서 그것을 무시했다. ⛔ 더 나쁜 것: 그 파일 머리말이 "호출자 셋(telegram·tui·api)" 이라 적고 있었는데 내가 그것을 「46일 늙었다」고 선언했다. 머리말이 맞았다.

🔑 그래서 남은 진짜 결손은 CLI 다 — 터미널에서 harness say 로 쏘는 길은​

하니스로 바로 가고 인테이크(트리아지·도메인·페이즈 분해)를 거치지 않는다. pwa·voice 도 선언만 있고 생산자가 없다.

🔑 wf 는 고립이 아니라 «가장 얇게 붙은» 축이다. 끊긴 변은 딱 둘 — 하니스↔wf · intake↔wf.​

⇒ 「wf 를 살린다」는 새로 짓는 일이 아니라 저 두 변을 잇는 일이다.

❹ 하니스 통합 — 여덟 자리 중 «둘»이 46일째 그대로다​

좌표는 이미 있다(REPORT-nl-to-harness-control-points-2026-08-07 §10). 그 여덟을 오늘 다시 눌렀다:

✅ ⑧⑨  daemon-tools/self-implement.ts originalUserText → goalSourceText → authorGoal

③④ 때문에 session/chat.ts 경로에서 ctx.userText 는 구조적으로 undefined 다.​

⇒ 말 한 줄이 골이 되는 배관이 «한 경로에서만» 완비돼 있다. 출시 전에 닫을 칸이다.

❺ 셀프힐링 — 하니스가 스스로 트리아지하고 정리한다​

분류     src/self-implement/abandoned-classification.ts   중단 런의 «이유»를 어휘로 낸다
         artifact-deficit · budget-exhausted · contract-conflict · credential-failure
         already-satisfied · completed-without-changes · cited-evidence-exists-without-changes …
         ⊕ environment-*-outranks-run-stage-evidence  ← 「환경 탓」과 「자식 탓」을 «우선순위»로 가른다

판정     src/self-implement/rework-budget-judgment.ts    wf classify 노드로 rework 예산을 판정
         src/self-implement/classify-shadow.ts           그림자 분류(실행 않고 비교)
정리     elanous harness clean                             워크트리·브랜치 회수 (수명 사다리 ⊕ 소유)
수리신호 elanous self repair-signals · elanous self parked

🔲 안 쟀다: 이 트리아지가 «실제로 얼마나 자주 옳은가». 어휘는 풍부하나 정확도를 잰 적이 없다.

❻ 네 가지 우주 — 자식을 띄우면 갈린다​

prod · prod→격리 · test · test→격리

부모/owner/checker 가 각자 우주를 정해 갈린다. 우주는 effectiveInstanceRoot() 로 한 번 해석하고 그 값으로 자식을 못 박는다. ⛔ 작업 디렉토리는 «별개 축» — 우주만 격리하면 사람 트리가 자식의 쓰기 구역이 된다.

📏 elanous where · elanous harness worktrees

❼ 세계를 보는 눈은 «빌린 것»이다​

📏 재는 명령: rg -c '^\s*- id:' catalog/resources.yaml

자원 맵 catalog/resources.yaml — 항목마다 「없으면 무엇이 안 되나」(free_fallback)를 적는다
  ✅ 있다   firecrawl · tavily · jina · 각 LLM 프로바이더 …
  ❌ 없다   omni-crawl · aside · CDP/Chrome
            ↑ 「깔려 있어야 하는 바이너리·브라우저」라는 «의존의 한 종류»가 통째로 빠졌다
  ⚠️ 자격이 필요한 항목의 다수가 free_fallback 칸이 «비어 있다»

🔑 무료 폴백이 «적혀 있는» 능력만 「코어」로 내보낼 수 있다. 이 칸이 곧 오픈코어 경계선이다.​

⛔ 이 문서가 «일부러» 안 그린 것​

① 끊긴 변을 이어진 것처럼              — harness↔wf · intake↔wf 는 «0»이다. 그대로 뒀다
⑤ 트리아지 «정확도»                    — 어휘는 셌고 「맞는가」는 안 쟀다
② 「눈·손·기억이 N 번 맞물린다」의 N   — 안 쟀다
③ 채널별 완성도                        — 파일 수로는 세었으나 «동작»은 안 눌렀다
④ 수를 본문에 박기                     — 전부 「재는 명령」으로 뒀다
