### ⛔ 그래서 ④ 와 ⑥ 이 «다른 물음»인 이유가 여기서 보인다

```
④ 「다른 답을 낼 수 있나」   ⇒ rg -c 는 «통과한다» (배선 안 하면 0 이 나온다)  ✅ 죽은 칸은 아니다
⑥ 「모양인가 도는가」        ⇒ rg -c 는 «실패한다» (import 만 해도 참이 된다)  🚨 여기서 걸린다
⇒ 📌 ***④ 만 보고 「판정 가능하다」로 넘기면 ⑥ 을 통째로 건너뛴다.*** 이 창이 그렇게 했다.
```

### 🩹 그래서 무엇을 쓰나 — **이 저장소에 «모범»이 있다**(2026-08-24 착지)

```ts
// src/self-dev/entrance-registry.test.ts — 진입점을 «실제로» 태운다
const { program, setRunDevAskFromGoalFileDepsForTesting } = await import('../index.js');
setRunDevAskFromGoalFileDepsForTesting({ … 무엇이 불렸는지 배열에 담는다 … });
await program.parseAsync(['node','elanous','harness','ask','/tmp/goal.md']);
expect(launchedEntrances[0]).toBe(CLI_HARNESS_ASK_ENTRANCE.id);
```
⭐ 같은 파일의 **종전 판본**이 정확히 반대였다 — `expect(indexSource).toContain('…_ENTRANCE.id')`.
그 문자열 가드는 **두 방향으로 틀렸다**: 리터럴이 사라지면 성질이 멀쩡해도 빨간불이고,
***리터럴만 있고 다른 이름을 넘겨도 초록***이었다(= 막으려던 것을 못 막았다 · `OBS-T289`).

### 📌 ⇒ **⑥ 을 채우는 한 줄**

> ### ***판정 신호에 `rg -c <심볼>` 을 쓰려거든, 「그 심볼을 «부르는» 자리가 이미 테스트에 있나」를 먼저 물어라.***
> 없으면 그 신호는 ***「배선했다」가 아니라 「이름을 적었다」***를 잰다.

## 📏🚨⭐⭐⭐⭐ **⑦ 이 «칸»이 된 근거 — 하루에 «세 번» 같은 형태였다** (2026-08-24 · `[T]` 125차)

> 이 문서의 규칙은 **「같은 형태가 두 번이면 칸을 더한다」**다. 셋이 나왔다.

```
① [launch-branch] current branch is …, not main
   🅰️ 「내 착지 루프(브랜치 전환)가 도는 골의 전제검사와 겹쳐 중단을 만든다」
   📏 경고 있음 58런 ***53%*** / 없음 123런 ***51%***   ⇒ ❌ 차이 없음
   ⊕ 애초에 «틀린 축»이었다 — 그 경고의 목적은 실패 예측이 아니라 ***base 선택 정확성***

② `ask-launch` 축이 `harness ask` 를 못 본다 (OBS-T285)
   🅰️ 「그러니 입구 매뉴얼의 「29발 중 0발」도 이 축 오류였을 것이다」
   📏 `cli-harness-ask` 최초 관측 = 2026-08-22T13:54Z ⇒ ❌ 그 「0발」은 «쓸 때 참»이었다

③ `goal-file-lint: WARN [out-of-target-requirement]` (JDG-T65)
   🅰️ 「이 경고 때문에 자식이 «어디에 쓸지» 못 정하고 변경 0으로 끝냈다」
   📏 경고 있음 65런 ***66%*** / 없음 127런 ***42%***  ⇒ ❌ ***반대 방향***
```

> ### 🔑 ***경고를 하나 발견하면 그것으로 눈앞의 미스터리를 설명하려는 «인력»이 있다.***
> 경고는 **「거기 있다」는 이유만으로** 가장 그럴듯한 원인으로 보인다. 그리고 셋 다 ***진짜 경고***였다 —
> 문제는 경고가 틀린 게 아니라 ***내가 그것을 「이 실패의 원인」으로 «승격»시킨 것***이다.

### 🩹 그래서 이 칸의 검사는 «한 줄»이다

```bash
# 그 경고를 받은 런과 «안 받은» 런의 완주율을 센다 — 안 갈리면 원인이 아니다
grep -l '<경고 문자열>' <산출들> | …   ⇒ completed 비율
grep -L '<경고 문자열>' <산출들> | …   ⇒ completed 비율
```
⭐ 세 번 다 ***재서 반증했다.*** 규율이 없었으면 셋 다 「원인」으로 굳었을 것이다.
⛔ ⊕ **③ 의 진짜 기전은 따로 있었다**: ***「읽기만 하라」고 이름을 대도 저작기가 그 파일을 «대상»에 넣는다***
   (ask 선언 2개 → 저작된 골 5개). 그러나 그것도 «실패의 원인»으로는 **미증명**이다.

## 🔁 이 문서를 고쳐야 할 때
같은 형태의 실패가 **두 번** 나면 칸을 하나 «더한다». ⛔ 지우지 않는다 — 이력이 값이다.
⭐ **다만 그 형태가 «이미 있는 칸»의 것이면 칸을 더하지 «말고» 그 칸에 실물을 붙인다**(2026-08-11 · 위 §③ 실물).

## ⛔ `harness ask` 와 `harness say` 는 «다른 것»을 받는다 (2026-09-10 🅣 · 실측)

`harness ask --help` 가 말한다: **`<goal-path>`** — ***"골 문서 경로를 받아 구동한다"***.
`harness say --help`: **`<sentence...>`** — ***"문장을 받아 구동한다"***.

🩸 **이 창은 손으로 쓴 골 파일을 `ask` 에 주고 «세 번» 막혔다.** 매번 다른 얼굴로 막혀서
매번 다른 것을 고쳤고, 셋 다 진짜 원인이 아니었다:

| 시도 | 막힌 문면 | 내가 고친 것 | 실제 |
|---|---|---|---|
| ① | `(대상 경로 0)` | 1행에 `대상 경로:` 라벨을 붙였다 | ❌ 여전히 0 |
| ② | `## REQUIRED EVIDENCE 절에 … 항목이 없다` | 그 절을 손으로 썼다 | ❌ 여전히 0 |
| ③ | `(대상 경로 0)` | `- RootIntent:` 줄을 넣었다(추측) | ❌ 여전히 0 |

⭐ **진짜 이유는 lint 가 «이미 말하고 있었다»** — 나는 그 줄을 읽고 지나쳤다:
```
[dev] goal-file-lint: WARN [canonical-structure] missing required section: ## WHAT TO BUILD
[dev] goal-file-lint: WARN [canonical-structure] missing required section: ## TRACED PATHS
[dev] goal-file-lint: WARN [canonical-structure] missing required section: ## 답하지 못하는 것
[dev] goal-file-lint: WARN [canonical-structure] missing required section: ## 불변식
[dev] goal-file-markers: … recognized invariant candidates are counted only inside the
      Original ask block, but this goal file has no Original ask block.
```
⇒ ***`ask` 로 주는 골 문서는 「하니스가 저작한 것」이 전제다.*** 대상 경로도 불변식도
**`Original ask` 블록 안에서** 세어진다. 손으로 그 구조를 흉내 내는 것은 길이 아니다.

### ✅ 규율

- 손으로 쓴 문면은 **`harness say "<문면>"`** 으로 쏜다. 첫 줄에 `대상 경로: …` 라벨을 둔다.
  ⇒ 하니스가 «자기 골 문서»를 저작하고 그 안에 `Original ask` 블록을 만든다.
- 대표 지시(*"dev 골은 항상 문서로"*)는 **여전히 지킨다** — 골 원문을 `docs/goals/` 에 «기록»으로
  남기되, ⛔ **그 파일을 `ask` 의 입력으로 쓰지 않는다**. 둘은 다른 역할이다.
- `ask` 는 **하니스가 만든** 골 문서를 다시 돌릴 때(재발사·수리 라운드) 쓴다.

📏 **반증**: 손으로 쓴 파일로 `harness ask <file>` → `(대상 경로 0)` 으로 막힌다.
같은 문면을 `harness say "$(…)"` 로 → `요청문이 선언한 대상 경로 3개 · ✅ 막는 것 없음`.

⛔ **교훈은 「문을 외워라」가 아니다** — ***막힌 문면이 «두 번 같으면» 내가 고치는 축이 틀린 것이다.***
①과 ③이 **글자 그대로 같은 줄**이었는데 나는 사이에 ②를 고치느라 그걸 못 봤다.
