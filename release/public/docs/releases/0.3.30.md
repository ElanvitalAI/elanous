# Elanous 0.3.30

- A shell command that runs longer than 10 seconds keeps running in the background and the turn continues; its result comes back when the command finishes.
- In the Next terminal, a background shell command can watch its output for a pattern; when a matching line appears, Elanous gets one notice and picks it up in the conversation, and a background command that finishes reports back to the conversation.
- `eln pane list`, `eln pane read` and `eln pane send` reach the panes of your Elanous Side workspace from the regular CLI (beta); `--enter` sends the text and presses Enter.
- The first time you open `els`, a shell pane opens for you with a short guide line; pane output streams to the screen as it arrives, the status line fits narrow terminals, and herdr spaces fold under one entry until you open them.
- `els status <pane>` shows whether a pane is working, idle, exited or unknown (with the reason), whether its input is empty, how long since it last printed, and which tool is running; `--json` gives the same as data.
- `els list` shows each pane's state as a badge, such as [▶ working].
- `els grep "<text>"` searches the last screen of every pane, including remote ones, and lists each matching line; secrets in matched lines are masked.
- The `els` attach screen supports the mouse: click the sidebar or tabs to switch, scroll back with the wheel, and other clicks go through to the pane.
- The `els` attach screen has ⏏ background and ✕ quit buttons at the right of the bottom line (also ctrl+b q and ctrl+b Q): background leaves everything running, and quit closes this space, asking first if something is still running.
- In `els`, press ctrl+b : and say what you want in plain words (for example, add a tab or rename a workspace); els shows a one-line preview of the plan, runs it on Enter, and asks for y before closing anything.
- In `els`, when the last pane's shell exits, the els view closes and returns you to your terminal; otherwise focus moves to the next live pane. Reopening `els` attaches a live pane or opens a fresh shell, and exited panes stay listed, dimmed.
- In `els`, a shell pane that starts eln, codex, claude or grok is shown as that agent in the tab row, `els ls` and `els status`, and goes back to a shell when the program exits.
- In Elanous Side, when a remote host stops answering, its last panes stay in the space list and tab row marked ?, and the status line shows ⇄host ? until it answers again.
- In web chat, pasting very long text (tens of thousands of characters) keeps the input box compact with a folded preview you can expand, sends the full text, and shows a line while the reply is streaming.
- In chat on your Nexus, the assistant can search and read the notes folder you chose during setup, read-only and limited to that folder.
- On your member home, a member who has not chosen a handle is sent to the handle step on the website, and once a handle is chosen the home shows your member address.
- When you resume a chat after restarting Elanous, the first turn works only on your new message; it does not redo or continue a request from before the restart unless you ask it to.
- If a model stops streaming after it has already asked for a tool, the tool still runs once and the next step goes to your next provider instead of retrying the stalled one.
- Elanous recognizes the context size of models from known remote providers, including through OpenRouter, so long sessions compact at the right time; local or unknown models keep the safe default.
- `els send` delivers long text in full, using bracketed paste when the pane supports it, and checks that the pane started working; in a pane without paste support it sends a single line only and refuses text with line breaks or control characters.
- In Elanous Side, if an ACP agent pane fails to stop, the pane stays in place and closing it again retries the stop.
- The destructive-command check looks at what actually runs: a command that only prints or searches text, such as `echo "rm -rf x"`, goes through without a warning, while quoted forms such as `"rm" -rf x` or `git "reset" --hard` are caught.
- `graph run` calls the model for prompt steps that declare JSON output and follows the verdict to the next step; before, those steps always failed.
- Resuming a workflow run from another checkout of the same files works; the run is refused only when its workflow files actually changed.
- The `chat.conciseness.flatBullets` setting is removed: answers always use flat bullet lists, and an old value is dropped from your config when it is read or saved.

## Perf

- When a long-running task continues on its own at the end of a turn, the next turn starts right away instead of about 10 seconds later.

## Security

- `els acp serve` rejects ACP extension methods, so a connected client cannot open or type into terminals outside the workspace's controls.
- With `els mcp serve`, a risky command sent to a pane (such as `rm -rf`) waits for a person to approve it on your approval channel; a denial, no answer, or no channel means it is not sent. Secrets in the command are hidden in the approval message.
- Tool activity rows in the Next terminal hide more secrets: passwords in ftp, ssh and database addresses, key values in query strings, and any command whose quoting cannot be read safely.

## Known issues

- The full pre-release test sweep for this version did not finish before publishing; the checks it did complete showed no new failures compared with the previous release, and the remaining checks are tracked for the next release.
- In the web app, three checks on the intake page (actions disabled for an empty field, URL previews absorbed without submitting, and classification offered for an unknown rule without calling a model) did not pass in the release test run and are tracked for the next release.
