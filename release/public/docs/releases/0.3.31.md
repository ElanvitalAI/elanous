# Elanous 0.3.31

- Your member address (yourhandle.elanous.app) opens your web chat from the member home and replies stream in; if you are not signed in, it shows a button to sign in as a member.
- Research answers in web chat now come back with source links, and a source link opens in a new tab so your conversation stays open.
- In web chat opened from your member address, you can attach .txt, .md and .docx notes: they are read in your browser, secrets in them are hidden before sending, and PDFs, other formats and oversized files are refused with a reason.
- When finance tools are turned on, research answers to market questions look up market data first and name it as the source of their figures; if a lookup fails, the answer says the figure could not be checked instead of guessing.
- The `els` tab row shows tab names in capitals, the active tab in blue and other tabs in gray.
- In `els`, clicking + in the tab row or pressing ctrl+b c asks for the new tab's name: Enter saves (an empty name gives the default tab), ctrl+c clears and Esc cancels.
- In a terminal narrower than 80 columns, `els` folds the side list into a top row showing the current tab with ▾; click it or press ctrl+b s to pick another space or tab.
- In the `els` view, scroll up into a pane's earlier output with the mouse wheel, or a page at a time with ctrl+b [ and ctrl+b ]; typing anything returns to the live bottom.
- `els import herdr` reads your herdr spaces, tabs and folders, shows a plan, and after you confirm creates only the missing panes in els as shell panes; herdr itself is not changed and running it again creates nothing new.
- `els snapshot <pane>` saves a picture (SVG) of a pane's screen, and `els record <pane>` starts recording a pane; run it again to stop and save the recording as an asciicast (.cast) file.
- When eln runs inside an `els` pane, a workflow graph run shows in the side list as a tree of its steps, each marked as it runs, finishes or fails.
- eln inside an `els` pane opens its side tab in place; a standalone eln, while an els server is running, moves the same session into an els pane when you toggle the side tab, and keeps its own side tab if that move is not possible.
- When the `els` server stops or restarts, an open els view says the server is stopping and reattaches when it is back, and a pane that had to restart shows its last saved screen.
- In `els`, a new tab reaches its prompt in about 0.13 seconds in our measurements (about 1 second before), and the first `els` start takes about 2 seconds (about 3 before), because your login shell settings are read once per els server run instead of for every tab.
- Research answers finish sooner: research stops searching at a set time limit and answers from the sources it has already found, and a request for a short answer keeps its short format.
- The eln side tab follows the `els` list as soon as it changes instead of checking once a second.
- In the `els` view, underlines and long lines in a pane no longer spill into the side list, and a pane running eln no longer shows lines twice while it redraws.
- Mouse clicks and the wheel in the `els` view now work in a regular terminal: mouse reporting turns on when the view opens and off when you leave it.
- In the `els` view, a remote host that stops answering is marked ✕ instead of ?, matching the eln side tab, and a remote pane's tab title starts with ⇄host.
- In the web chat screen, notices that conversations or activity could not be loaded no longer appear, and the conversation list, menus and device-connect prompt that do not work there are hidden.
- In web chat, an answer that is still streaming appears in the message itself instead of only inside the details fold.
- Research answers show the note that some searches were incomplete only when a search actually failed.
- In research answers, figures from earlier replies in the same conversation are treated as unverified and are not repeated unless this answer's own sources back them.
- In Elanous Side, if an ACP agent pane fails to start and cleaning it up also fails, the pane stays reserved instead of being reopened, and closing it retries the cleanup.
- After you stop a reply with Esc, or a reply stalls or times out, the next turn is told why the previous one stopped.
- A background agent step that only says what it is about to do, without doing anything, is asked once to do the work instead of being reported as finished.
- The `chat.autoCopyQaToClipboard` setting is removed: chat answers are not copied to the clipboard automatically, and an old value is dropped when your config is saved.
- Elanous Side no longer passes its owner credential to panes, and refuses requests to change panes from a program inside a pane that has no credential of its own; your own terminal uses a private owner credential file so you can keep typing into panes.
- Web chat opened from a member address serves only the app's own built files (scripts, styles, fonts and icons); source maps and other files are not served.

## Known issues

- Part of the pre-release test sweep for this version could not finish: a few long-running interface tests stop responding in the test environment and behave the same way on the previous release, and some other checks were affected by test-environment factors. All checks that completed showed no new failures compared with the previous release; the unfinished and environment-affected checks are tracked for the next release.
