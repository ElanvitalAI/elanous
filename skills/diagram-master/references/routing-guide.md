# 엔진 선택 상세 가이드

## 실행 모드

| 모드 | 키워드 | 동작 |
|------|--------|------|
| **auto** (기본) | 별도 지정 없음 | PDF 원본 추출 우선, 나머지만 엔진으로 생성 |
| **recreate** | "재생성", "다시 그려", "스킬로", "recreate", "새로 만들어" | PDF 추출 스킵, 모든 다이어그램을 엔진으로 새로 생성 |

### recreate 모드 워크플로우

```
1. PDF 원본의 다이어그램을 Read tool로 시각적으로 분석
2. 구조, 레이블, 데이터 값, 축 범위 등을 추출
3. 콘텐츠 유형에 따라 최적 엔진 자동 선택 (Step 1~5)
4. 엔진으로 동일 내용을 새로 생성 (통일된 스타일)
5. 원본과 비교 검증
```

**장점**: 편집 가능, 해상도 무손실, 스타일 통일, 웹 인터랙티브 가능

## Decision Tree (순서대로 판단)

```
┌─────────────────────────────────────────────────────┐
│ Step 0: 모드 판단                                    │
│   → recreate 모드: Step 0a 스킵, Step 1로 직행       │
│   → auto 모드(기본): Step 0a로                       │
├─────────────────────────────────────────────────────┤
│ Step 0a: PDF에 이미 고품질 다이어그램이 있는가?       │
│  [auto 모드 전용]                                    │
│   → YES: PDF 추출 (재생성 불필요)                   │
│   → NO: Step 1로                                    │
├─────────────────────────────────────────────────────┤
│ Step 1: 사용자가 엔진을 명시했는가?                  │
│   "mermaid로", "matplotlib으로", "excalidraw로" 등   │
│   → YES: 해당 엔진 사용                             │
│   → NO: Step 2로                                    │
├─────────────────────────────────────────────────────┤
│ Step 2: 인터랙티브 요청인가?                         │
│   키워드: interactive, 버튼, 토글, 호버, 클릭        │
│   → YES + 대규모 데이터(1000+): D3.js               │
│   → YES + 일반: SVG interactive                     │
│   → NO: Step 3으로                                  │
├─────────────────────────────────────────────────────┤
│ Step 3: 수학적 정밀도가 필요한가?                    │
│   함수 곡선, 분포, 히스토그램, 축/눈금 정밀,          │
│   3D plot, contour, 회귀선, 경제학 모델 곡선         │
│   → YES: Matplotlib                                 │
│   → NO: Step 4로                                    │
├─────────────────────────────────────────────────────┤
│ Step 4: 자유형 레이아웃이 필요한가?                   │
│   비정형 배치, 손그림 느낌, 곡선 연결,                │
│   정해진 그리드에 맞지 않는 구조                      │
│   → YES: Excalidraw                                 │
│   → NO: Step 5로                                    │
├─────────────────────────────────────────────────────┤
│ Step 5: 기본 — Mermaid                              │
│   흐름도, 구조도, 시퀀스, 상태, ER, 타임라인,         │
│   간트, 마인드맵, 클래스, 파이 차트 등                │
│   → 컨텍스트가 가장 단순하고 범용적                   │
└─────────────────────────────────────────────────────┘
```

## 엔진별 최적 시나리오 매트릭스

### Mermaid (기본, 최우선)

| 적합 | 예시 |
|------|------|
| 프로세스/워크플로우 | 회원가입 흐름, CI/CD 파이프라인 |
| 구조/계층 | 조직도, 시스템 아키텍처, 모듈 구조 |
| 상태 전이 | TCP 상태, 주문 상태, 게임 FSM |
| 시퀀스 | API 호출 순서, 인증 흐름 |
| 관계 모델 | ER 다이어그램, 클래스 다이어그램 |
| 시간 기반 | 타임라인, 간트 차트, 마일스톤 |
| 분류/범주 | 마인드맵, 파이 차트 |
| 수식 포함 구조도 | `@svg-katex` + `render_mermaid_katex.py` |

### Matplotlib (수학/과학 정밀)

| 적합 | 예시 |
|------|------|
| 함수 곡선 | sin/cos, 다항식, 지수/로그 |
| 경제학 모델 | 수요/공급, IS-LM, AD-AS, 필립스 곡선 |
| 통계 분포 | 정규, 포아송, 이항, t-분포 |
| 데이터 차트 | 히스토그램, boxplot, violin, scatter |
| 히트맵 | 상관행렬, confusion matrix |
| 3D 시각화 | surface, wireframe, contour |
| 정밀 축 | 로그 스케일, 다중 축, 커스텀 틱 |
| 수학 수식 라벨 | LaTeX 수식이 축/제목에 필요할 때 |

### Excalidraw (자유형)

| 적합 | 예시 |
|------|------|
| 개념 스케치 | 아이디어 브레인스토밍, 초기 설계 |
| 비정형 구조 | 자유 배치가 핵심인 아키텍처 |
| 손그림 느낌 | 프레젠테이션용 친근한 다이어그램 |
| 곡선 연결 | 부드러운 곡선이 필요한 연결선 |
| Evidence Artifacts | 코드 조각, JSON 포함 상세 다이어그램 |

### Nano Banana 2 (AI 이미지 생성)

| 적합 | 예시 |
|------|------|
| 해부학/의학 도면 | 인체 구조, 세포 다이어그램, 장기 단면 |
| 지리적 지도 | 특정 지역 지도, 지정학적 시각화 |
| 복잡한 인포그래픽 | 다단 레이아웃, 아이콘+텍스트+데이터 혼합 |
| 일러스트 스타일 | 교과서급 컬러 도면, 기술 일러스트 |
| 코드 비효율 도면 | 건축, 회로, 기계 장치 등 코드로 그리기 비현실적 |
| 참고 이미지 재생성 | PDF 원본을 `--ref`로 전달 → 깔끔한 버전 재생성 |

**명시 트리거**: "나노바나나", "nanobannana", "AI로 그려", "이미지로 생성"

**auto 라우팅 기준**: 다른 코드 기반 엔진으로 표현이 비효율적인 복잡한 시각물

**주의**: 출력이 래스터 이미지(PNG)이므로 편집 불가. 정밀한 데이터 정확도가 필요하면 Matplotlib, 편집 가능성이 필요하면 SVG/Excalidraw 사용.

### SVG (웹 임베딩 / 인터랙티브)

| 적합 | 예시 |
|------|------|
| 웹 배포용 | 블로그, 문서 사이트 임베딩 |
| 호버/클릭 인터랙션 | 프로토콜 탐색, 레이어 토글 |
| 애니메이션 | 입장 효과, 흐름 표시 |
| 접근성 필요 | ARIA 라벨, 키보드 내비게이션 |

### D3.js (대규모 데이터)

| 적합 | 예시 |
|------|------|
| 네트워크 그래프 | 소셜 네트워크, 의존성 그래프 |
| 지도 시각화 | choropleth, 지리 데이터 |
| 대규모 데이터셋 | 1000+ 포인트 scatter, 실시간 |
| 복잡한 인터랙션 | 드래그, 줌, 필터, 연결 탐색 |
| 트리맵/선버스트 | 계층 데이터의 비례 시각화 |

### PDF 추출 (재사용)

| 적합 | 예시 |
|------|------|
| 교과서 다이어그램 | 이미 잘 그려진 도면 재사용 |
| 복잡한 회로도 | 재생성이 비현실적인 전문 도면 |
| 손필기 스캔 | 교수 판서 다이어그램 보존 |
| 저작권 원본 | 원본 품질 유지가 중요할 때 |

## 경계 사례 판단

### Mermaid vs Matplotlib
- 구조 + 수식 라벨 → Mermaid (`@svg-katex`)
- 연속 곡선 + 정밀 축 → **Matplotlib**
- XY 데이터 단순 차트 → Mermaid `xychart-beta`도 가능하지만, 축 커스터마이징이 필요하면 Matplotlib

### Mermaid vs Excalidraw
- 규칙적 그리드 배치 → **Mermaid**
- 위치가 의미를 전달 (비선형 배치) → **Excalidraw**
- 텍스트 중심 + 깔끔한 연결선 → **Mermaid**

### SVG vs D3.js
- 정적 다이어그램 + 간단 호버 → **SVG**
- 데이터 바인딩 + 동적 업데이트 → **D3.js**
- 노드 100개 미만 → **SVG**
- 노드 100개 이상 → **D3.js**
