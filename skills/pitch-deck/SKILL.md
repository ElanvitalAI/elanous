# Pitch deck — 근거를 지닌 짧은 발표

## 언제 / 입력

회사 또는 제품을 5~10분에 소개할 때 쓴다. 입력은 **회사 한 줄 정의**, 저장소의 **사실 원천 파일들**(읽은 판본과 줄 위치), **발표 길이**다. 독자·구매자·공개 가능 범위를 먼저 정한다. 확인되지 않은 값은 매출·고객·시장 실적처럼 말하지 않는다.

## 장 구성

기본 뼈대 **일곱**: **정의**(한 줄로 무엇을 하나) → **문제**(누가 왜 멈추나) → **시장**(TAM·SAM·SOM, 출처 없으면 가정) → **기술/BM**(해결법·경쟁력·BM·누가 지불하나) → **성과**(검증된 사례·측정 또는 «아직 검증 전») → **성장 전략**(어떤 순서로 누구에게 닿나) → **팀**(누가 실행하나). **계획**은 기본 일곱과 *별도 마지막 장*: 제목·표지에 «계획 · 순서와 시기는 바뀔 수 있습니다»를 쓰고 월 단위 약속은 쓰지 않는다. 발표 길이에 맞게 기본 장 하나를 둘로 나누거나 오프닝을 더해 최종 8~12장으로 만든다.

첫 장은 **3초 안에 뜻이 전해지는 쉬운 한 줄**, 전문 용어 0. 다음 장에는 **실물 증거**를 둔다: 실제 화면의 자리와 시연할 행동을 명시하고, 이미지가 없으면 «화면 자리»라고 표기한다. 화면·시연은 검증 전이면 «계획»으로 구분하며 이미 된 일로 그리지 않는다. 사이트와 데모 대본의 메시지 순서(약속 → 증거 → 작동 원리 → 다음 행동)를 따른다. 설득 문장은 빠르고 쉬워도 기술적 아우라는 검증 가능한 실물로 뒷받침한다. 남의 이름·제휴 암시·«곧»·미측정 성과는 넣지 않는다.

각 장: **한 장 한 메시지**, 제목은 명사 나열이 아니라 **주장 문장**. 본문·제목을 합쳐 **공백 기준 45낱말 이하**(출처 ID·진행표시·접근성 라벨 제외). 넘치면 장을 나누고 핵심을 고른다. 수치·날짜·비율은 읽은 파일의 **파일:줄** 또는 공개 링크를 SOURCES의 개별 주장과 짝짓는다. 출처가 없는 시장 규모·추정 TAM/SAM/SOM은 장에 **«가정»** 표시하고 SOURCES의 가정 목록에도 적는다. 근거가 없으면 수치를 만들지 말고 측정 방법을 제시한다. 고객·매출·계약·기술 성숙도를 과장하지 않는다.

### 누구에게 파나 — ECP / ICP

ECP(early customer profile)의 **시급한 문제·사건/구매 트리거·현재 우회 비용·도입 준비**를 묻고, ICP(ideal customer profile)의 **조직/업종·규모·구매자·사용자·의사결정 권한·도입 제약**을 적는다. 시장 장에서는 ECP → ICP → 접근 가능한 구매자(SOM) 순서로 좁힌다. 기술/BM 장에는 구매자와 사용자, 값이 생기는 순간, 과금 가설을 서로 구분한다. 인터뷰 전인 칸은 «가정»이라고 쓰며 공개되지 않은 연락처·고객사 내부 수치를 옮기지 않는다.

## 작성 · 출력

1. 참고본은 `.eml`의 본문·첨부를 파싱해 **슬라이드 구조만**, docx/xlsx에서는 **칸 이름만** 참고한다. 참고본의 사람 이름·연락처·주소·내부 수치·원문 문구는 전재하지 않는다. 저장소의 브랜드 정본과 공개 가능한 기능 근거를 읽고 계획을 현재 성과로 바꾸지 않는다.
2. `template.html`의 CSS·JS를 각 덱 HTML에 **인라인 복사**하고 `<section class="slide" data-claim="…">`마다 하나의 메시지를 넣는다. 파일 밖 폰트·이미지·스크립트 의존성 없이 로컬 파일로 직접 연다. 제목의 주장 ID마다 SOURCES 표에 **같은 ID**, 출처와 그 줄에서 확인할 내용, 상태(사실/가정/계획)를 기록한다. 숫자 하나라도 별도 근거가 필요하면 같은 행에서 항목별로 대응한다.
3. 출력은 **한 파일 HTML 덱**, 키보드 방향키/스페이스로 넘김(화면 버튼도 제공), 16:9, 인쇄하면 한 쪽 한 장. 버튼·입력 요소에 초점이 있을 때는 슬라이드 단축키를 건너뛰어 기본 키보드 조작(«이전» 버튼에서 스페이스)을 보존한다. 인쇄 미리보기·첫/끝 넘김·숫자/개인 연락처를 확인한다. 디자인 시스템을 새로 만들지 않고 `내부 문서 `BRAND-CANON-elanvital-and-elanous-2026-09-30``의 색·서체 사용 기준을 따른다.

기존 연결: `src/skills/index.ts`의 `buildSkillIndex` → `listSkillNames`/`parseSkillMd`가 이 폴더의 SKILL.md를 발견한다. 덱은 스킬이 작성해 직접 여는 **독립 문서**이며 HTML을 위한 신규 런타임 라우트는 만들지 않는다.
