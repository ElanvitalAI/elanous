---
name: enterprise-task-analysis
description: Turn enterprise learning needs into traceable tasks and evidence requirements for NCS matching.
---

Use at the enterprise `task` stage after `enterprise-needs`. For each interview-backed work task, capture the learner role, input, action, output, observable performance criterion and interview section that supports it. Separate a concrete work description from a hypothesized task; mark absent frequency, tools, access permissions and proficiency `미확인`. Return job candidate keywords and bounded task descriptions for the existing `ncs-match` stage. A job title is a search candidate, not a confirmed NCS classification. Let `ncs-match` verify a code, name, level and source from the NCS service; never manufacture a code or promote a loose search hit to a confirmed unit.

In examples use fictional roles and organizations. Do not pass raw interview paragraphs into graph stdout: cite the heading or use a brief de-identified excerpt only where necessary. Do not invent internal company policy, course names or course URLs; write `미확인` if absent. If no concrete task is documented, state that the task basis is `미확인` and request clarification instead of drawing an unsupported NCS match.
