# GCP architect expand — declaration + offline simulation

`plugin.json` and `graph.yaml` retain the existing ticket-design workflow. `tiered-graph.yaml` adds the one-requirement, three-option simulation route. The operating provider for `cloud-resource.observe@1` reports `연결 없음` when `ELANOUS_GCP_OBSERVE_PROJECT` is unset; a configured project is observed only with `gcloud compute instances list`. The graph creates a requirements-only, unpriced architecture PDF, editable diagram and PNG through the shared deliverables graph. With no connection it pauses at a visible `connect-first` card: `클라우드 연결 필요 — 연결하면 이 설계로 배포 승인`. Acknowledging or deferring that card cannot enter provision. The result claims zero created or fake resources. Provision, schedule and idle-stop remain unprovided in the operating registry.

From the repository root run `bun scripts/gcp-architect-expand/sim/fake-world.ts`. The simulation creates temporary fake project/cost records, calls the existing resource lease ledger, checks the approval gate and deletes its temporary files. `realGcpCalls` must be `0`.

Membership feature grants are declared in `entitlements.json` with a deny-by-default policy. The public `detect` node consumes the generic feature checker with a free membership identity. Paid routes are absent until the host can supply a verified membership resolver. Graph input never controls membership. No plugin code branches on membership tier.

The older fake-world `detect` recipe reads self-dev host measurements and the harness queue. The operating capability uses the explicit GCP project setting above and never substitutes fake pressure or resource rows for a missing connection. A configured but unreadable project yields `unknown` and stops; it is not reported as an empty connected project. The remaining recipes still fail closed.

## Architecture output contract

`output-contract.json` requires an editable `.excalidraw` source, its PNG render, and an architecture design PDF containing background, requirements, architecture diagram, data flow, security grade, cost formula, savings, alternatives, and a decision record. The graph declares `design → diagram → pdf → verify` before the spending approval node. `src/ux-sim/gcp-architect-expand/verify-step.ts` checks the artifacts in `GCP_ARCHITECT_OUTPUT_DIR`; a missing or invalid file fails closed. The design, diagram, and PDF recipes remain unimplemented until a reviewed workflow supplies these outputs. No artifact is spending authorization.

The offline advanced design path accepts one classified requirement JSON with explicit traffic assumptions. `bun scripts/gcp-architect-expand/sim/run-tiered-design.ts` runs this plugin graph with a fake provider. The `design` result contains small, medium, and large alternatives; `deliverables` invokes the shared architecture-deliverables graph for each and writes three editable diagrams, PNGs, seven-page PDFs, and verification receipts under `.elanous-test/gcp-advanced-tiered-design/artifacts/`. The top-level `tiered-design-receipt.json` records all cost rows, synthetic rates, traffic inputs, artifact hashes, and the design confirmation and approval-resume result. The cost figures are deliberately synthetic and must never be shown as official GCP quotes. No GCP API or provisioning node runs in this path.

The committed [offline sample](sim/sample-output/) contains the editable diagram, PNG, HTML source, PDF, and fake-world event trace. Rebuild it from the repository root with `python scripts/gcp-architect-expand/sim/build-sample.py` in an environment with Playwright and Chromium installed. It calls the existing `skills/diagram-master` Excalidraw renderer and `skills/lecture-note-digitizer/references/convert_to_pdf.py` for PDF layout. The Excalidraw template pins the working package version because the unpinned CDN import currently fails on a missing transitive module.

The upgraded sample uses [official Google Cloud product/category icons](sim/assets/README.md), nested user device → project → region → VPC boundaries, six named layers, numbered flows, a legend, and a diagram version. The single six-page landscape PDF contains a cover, table of contents, executive summary, embedded diagram, tables, decisions, and source appendix. `icon-provenance.json` records the checked official icon source and hashes of icons embedded in the editable diagram; the verifier checks those hashes and the declared diagram/document structure. The PDF conversion script now honors CSS page size so its existing A4 default can produce this landscape document.

## Solar-only ticketing demo handoff

See [SOLAR-HANDOFF](demo/SOLAR-HANDOFF.md) for the three-line instruction and one-roundtrip command. The plugin accepts a ticketing design JSON from the Solar profile, reads this GCP decision pack and entitlement table, emits a cost-formula/security proposal, exercises the fake GCP world with synthetic approval, renders the editable diagram/PNG/PDF through existing skills, and verifies the output. The committed result is generated from a **synthetic ticket design fixture**. The live Solar profile supplies its own design result path; this plugin never specifies a provider, model, or `roleLlm` override. The production graph's real spending approval and fail-closed provisioning remain in force.

For a person-visible rehearsal, `scripts/gcp-architect-expand/demo/tui.py --test-universe` displays progress, an explicit fake-world `y/N` gate, and file-open choices. It writes an isolated `receipt.json` and never invokes real GCP. This preview does not replace graph HITL; the graph binding and automatic pack selection remain upstream prerequisites.

For the integrated six-scene demo, the actual classic TUI must search `route:GCP 확장안` through ToolSearch before executing the selected plugin route. Scene 5 is the displayed proposal plus approval receipt. Scene 6's GCPX-owned output is a [board attachment handoff](demo/BOARD-HANDOFF.md) with the exact optional `board.card.attachments` fields for the editable diagram, PNG, PDF, and HTML. The board event owners decide and display development/test/deployed states; this plugin records `deploymentStatus: unverified` until they supply those events.
