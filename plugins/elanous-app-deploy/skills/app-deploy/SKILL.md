# App Deploy

When the user asks to deploy a registered app, call app_deploy with its verified registered app ID and the user's request as requestText. Do not replace the requested app ID with a lecture template. The same tool serves TUI and PWA chat. The legacy lecture-scrap template retains its existing publisher; unsupported templates fail closed.

For a generated app, use the server-reserved source root and runId paired with the verified owner. Have app_create write source-artifact@1 at that root. After editing, run the relevant checks through RunShell or Bash before calling app_deploy with appId, runId and requestText; the verification action gate rejects a deploy call made before that step. The generated path inspects the sealed artifact, asks for human confirmation, then uses the authenticated Nexus route to start the local service and verify the public URL. Never supply a self-declared owner, root or artifact digest as authority. Without an approved test slot, artifact approval and relay token, publication fails closed.

The registered-template path requires a passing simulation receipt. Both paths ask `배포` with `y` and `N` (default `N`) immediately before public publishing. Only an explicit `y` publishes. Return the tool's structured `kind: "site-deploy"` status and the `publicUrl` only when published. A `simulated` result means the public publish hook is unavailable; do not invent a URL or use a shell publishing path.
